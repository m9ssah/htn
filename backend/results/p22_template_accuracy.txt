Stable across 3 consecutive runs at 15/15 and 9/9.

Three changes, in the order they were made:

1. POLICY. Route `other` now honours Jev instead of freezing the surface.
   `other` means the route question found no bucket, not that the user wants
   nothing. Deliberately NOT thresholded on confidence -- this very table is
   why (wrong at 0.93, right at 0.64).

2. CRITERIA. `item_detail`, `focus_step` and `generic_answer` rewritten so the
   line is "does answering need a number or a position the task computes?"
   Constraint 2 is the reason: `generic_answer`'s content is model-generated,
   so routing "what are the ingredients" there at 3x batch would have a
   language model generate the quantities.

3. SURFACE. Contacts gained `near`, rendered as the ListItem's second line.
   Before this, "who lives closest to me" sat at people_picker 0.43 /
   generic_answer 0.42 and flipped between runs -- the model could not tell,
   correctly, because NEITHER surface held an answer. Routing it without
   showing location would have moved the failure, not fixed it.

TypeSafe exposes no fine-tuning endpoint (/v1/fine_tuning/jobs -> 404,
/v1/models -> 200), so Jev is a fixed judgment model. Everything above is
question text, policy and surface content -- the levers p18b/p18c already
measured as the ones that move this number.
